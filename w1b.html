第 1 周补充 · 一条命令怎么跑

把「路径 / 目录」和「进程」连起来的那根线 ｜ 2026-11-11

一、为什么非要懂这个

你在终端敲 ls，屏幕就吐出一屏文件名。看起来是一瞬间的事，其实中间发生了四件事。

不懂这四件事，以后你装 PX4、跑 ROS2，屏幕上蹦出下面这些字，你只能干瞪眼：

  • command not found —— 命令找不到
  • No such file or directory —— 文件找不到
  • Permission denied —— 不让你干

这三句话，是四步里不同步骤断掉时说的话。知道断在哪一步，才知道该改什么。

二、三个角色

角色是谁只干一件事
终端
Terminal		你敲字的那个黑窗口收你敲的字、把结果打出来。它自己不懂命令
Shell
命令解释器		Windows：cmd / PowerShell
Linux：bash		看懂你写的那行字，负责找到该跑的程序
进程
Process		真的在跑的那个程序干活。干完就消失
终端 = 传话窗口；Shell = 管家；进程 = 工人。
你递一张纸条给管家，写「拿锤子 钉子」。管家负责去工具箱找到锤子，再叫一个工人去砸。工人干完活走人，钉子盒还在原地。

三、四步

  1. 你按回车 → 终端把这一整行字交给 shell。
  2. shell 拆词 → 把第一个词当「程序名」，去 PATH 里列的目录中挨个找；找到就停，不再往下找。
  3. 系统建进程 → 找到后，操作系统新开一个进程，把后面的词当「参数」交给它。
  4. 干活并回话 → 进程运行，把结果写到屏幕；结束时进程消失。

PATH 是什么？一张「程序搜索目录清单」。shell 只在这几个目录里找可执行文件。不在清单里的程序，就得写全路径才叫得动它。

四、最关键的一条区分

命令 = 程序名 + 参数。这两半是按完全不同的规矩找的：

怎么找例子
第一个词（程序名）靠 PATH 清单找ls、python
后面的词（参数）靠当前目录或你写的路径找进度.md、D:\code\a.py

这就解释了两件你迟早会撞上的事：

  • ls 在哪个目录下敲都能用——因为它在 PATH 里，跟你在哪无关。
  • python 进度.md 却要求 进度.md 相对当前目录写对——因为它是参数，靠当前目录算。
一句话：程序名靠「通讯录」找，参数靠「你现在站哪儿」找。
这就是上一张卡片里「当前目录」为什么那么重要的真正原因。

五、怎么做：验证一个程序在哪

想确认 shell 是从哪找到某个程序的，直接问它：

系统查程序位置看 PATH 清单
Windowswhere pythonecho %PATH%
Linuxwhich python3echo $PATH

打印出来的那一串目录，就是 shell 找程序时会去翻的抽屉。

六、自测（先自己想，再点开）

1. 终端和 shell 有什么区别？

终端只负责收字、显示字，它不懂命令；shell 才负责看懂那行字、找到该跑的程序。

2. PATH 是什么？为什么它能让 ls 到处都能用？

PATH 是 shell 搜程序的目录清单。ls 在本机某个 PATH 目录里，shell 每次都能翻到它，所以跟你在哪个目录无关。

3. 报 command not found，断在第几步？

第 2 步：shell 在 PATH 里翻遍了也没找到这个程序，根本没到"建进程"那一步。

4. 报 No such file or directory，断在第几步？

通常在第 3 步之后：程序找到了、也跑起来了，但它按你给的路径（参数）去开文件，发现没有这个文件。
