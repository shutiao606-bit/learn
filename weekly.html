这页是干什么的

一个人闷头学，最大的风险不是学得慢，是学了半年才发现方向早就变了。

所以每周花 10 分钟，看一眼这个圈子里在发生什么。

三条规则：

  1. 只看和主线有关的，别的刷到也划走
  2. 不 clone、不安装、不跑。这页只是"知道你站在哪"
  3. 10 分钟到点就关，不追更

先学会一件事：看目录

下面每个项目，我都给了顶层目录。这不是凑字数——看目录是一个项目最快的读法。

一个成熟仓库的目录名，基本就说明了它的世界观：

看到这个大概率放什么
src/真正的源代码
docs/ start_here/给人看的说明。愿意写这个的，通常比较成熟
scripts/一次性小工具，装环境、批量跑
tests/自动检查代码有没有坏
examples/ baselines/可以直接照着跑的样例

这跟你第 1 周学的「路径与目录」是同一件事：目录结构 = 作者脑子里的结构。

本期 5 条

1. aerial-autonomy-stack（AAS）

660 ★ ｜ C++ ｜ 最后更新 2026-11-12（就是昨天）｜ GitHub

它是什么：一个"电池已装好"的无人机自主性开发栈。官方介绍就三句话：开发多机自主（PX4 / ArduPilot / Betaflight）、仿真感知与控制（YOLO + 3D 激光雷达，快于实时）、部署到真机（JetPack / DeepStream / NVIDIA Orin）。

顶层目录说明了什么：

start_here/入门文档，里面有 BOM（物料清单）和"为什么这么设计"的说明
aircraft/机型：四旋翼、垂直起降（VTOL）、尾座式、固定翼
simulation/仿真世界的配置
ground/地面侧的东西（监控、地面站）
aas-gym/强化学习训练环境，按 gymnasium 的接口做

为什么和你有关：这就是你 6 周之后要一步步自己搭出来的东西的"标准答案版本"。你现在不用懂它，但可以先认识这几个词：PX4 是飞控、Gazebo 是仿真世界、YOLO 是视觉、Jetson 是机载小电脑——这四个词会陪你走完整个研一。

这周能做什么（5 分钟）：只看 start_here/ 里那份 BOM。那是"造一台能自主飞的四旋翼要买什么"，看完你会第一次有"这东西有实体的"的感觉。

2. Langostino

553 ★ ｜ Python ｜ 最后更新 2026-02 ｜ GitHub

它是什么：一个用 ROS2 + AI 做自主飞行的开源参考平台，目标是"一个能读懂、能复制、能改"的真实无人机自主系统。

顶层目录说明了什么：

src/核心代码
model/训练好的模型文件
scripts/装环境、启动用的脚本
mapproxy/地图服务（它需要地理数据）
inav-custom-firmware/自己改过的飞控固件

最有价值的一点，不在代码里：它走的是树莓派 + iNav 固件 + GPS + 激光雷达这条路，而不是 PX4。
也就是说，同样叫"无人机自主飞行"，业界至少有两种完全不同的搭法：一种是 AAS 那种 PX4/ROS2 的重型方案，一种是 Langostino 这种树莓派上的轻量方案。知道有两条路，比只会一条重要得多。

这周能做什么（5 分钟）：把它的顶层目录和上面 AAS 的顶层目录对照着看。同样是无人机项目，为什么这边有 mapproxy/ 和 model/，那边有 simulation/ 和 aircraft/？这个差别，就是两条路线的差别。

注意：这个仓库 2026 年 2 月之后没再更新，相对不活跃。它适合用来"看结构"，不适合当"跟着做"的教程。

3. FlowPilot —— 让无人机"边想边飞"（论文）

arXiv 预印本 ｜ 2026-11-02 接收 ｜ 北京理工大学等 ｜ arXiv

它是什么：一篇讲"敏捷无人机导航"的论文，用的是世界-动作模型（world-action model）的路子：不再拆成"先感知、再规划、再控制"三段，而是让一个模型直接输出该怎么飞。作者承诺开源代码。

为什么这个思路值得你知道：

  • 传统无人机自主：感知 → 规划 → 控制，三个模块，接口清晰，但中间每一环都可能丢信息
  • 大模型这一派：看到画面，直接给出动作，中间不拆
  • 这就是"具身智能"进到无人机领域的方式，也是你说的 VLA 的同一个思路

为什么和你有关：你的方向是集群 + VLA。这类工作就是那个交叉点上的东西。你现在不需要看懂方法，只需要知道：这个圈子里有一批人正在把"大模型直接控制无人机"这件事往前推。等你到 VLA 小项目时，你会回来找这类论文。

这周能做什么（3 分钟）：只看摘要的第一句和最后一句结论。看不动没关系——能感觉到"看不懂但知道它在干什么"，就已经是进步了。

4. Xiaomi-Robotics-0 —— 国内开源 VLA 的代表（背景补课）

2026-02 开源 ｜ 约 47 亿参数 ｜ Apache-2.0 ｜ arXiv

它是什么：小米的第一代机器人 VLA 大模型，代码和权重都开源了。结构上是"视觉语言大脑 + 扩散动作专家"：一个模型负责看懂画面和指令，另一个负责把"要干什么"变成平滑连续的动作。

它解决什么问题：机器人在真实环境里做动作，最怕的是卡顿和抖动——模型算得再准，动作一卡一顿也没法用。这类工作很大一部分精力花在"怎么让动作连贯、实时"上，而不是"怎么更聪明"。

为什么和你有关：这是目前国内最有代表性的开源 VLA 之一。你要记住的最重要一句话是：

2026 年做 VLA，不是"从头造一个模型"，是"拿一个开源模型来微调"。

这直接决定了你以后小项目的样子：不是训练，而是准备数据 → 微调 → 部署 → 评估。现在知道这一点，你学 Python 和数据处理的时候会更有方向感。

这周能做什么（2 分钟）：什么都别做，就记住上面那句话。

5. Psi0（Ψ₀）—— 人形机器人 VLA，RSS'26 收录

2887 ★ ｜ Python ｜ 最后更新 2026-11-11 ｜ GitHub ｜ arXiv

它是什么：一个人形机器人的开源基础模型，目标是"通用的全身移动 + 操作"（loco-manipulation）。仓库里带了模型、数据、训练脚本和 Docker 配置。

顶层目录说明了什么：

src/模型与训练代码
real/真机部署部分（和仿真分开写，这是个好习惯）
baselines/对照方法，用来证明"我这版更好"
docker-compose.yml一键把环境跑起来
flake.nix nix/另一种环境固化方式（更硬核，知道有这么回事就行）

为什么和你有关：你的课题里有双机械臂。人形 VLA 和双臂操作，在"两只手怎么配合"这一层是相通的。以后你查资料，loco-manipulation、dual-arm、bimanual 这几个词会反复出现。

另外注意一个细节：它把 real/（真机）和仿真代码分开放在顶层。这是个很成熟的工程习惯——真机代码和仿真代码混在一起，早晚出事。你现在不用照做，先记住这个分法。

这周能做什么（5 分钟）：看 README 里的动图或视频链接，感受一下"人形机器人 VLA"现在能做到什么程度。

一句话连回你这周

这五条看着离你很远，其实都站在同一个地基上：

上周你学的 PX4、Gazebo、YOLO 节点，都是独立进程，靠话题和端口互相说话。上面这些项目，说到底就是把这些进程组织得更好——目录怎么分、谁先启动、出错怎么查。

所以这周读 ③ 进程、④ 路径的时候，别觉得"跟无人机没关系"。关系就是：所有这些项目跑起来之后，你都要靠这几样本事去认它们、停它们、修它们。
