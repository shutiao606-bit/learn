②B 它凭什么找得到

PATH、程序名、参数、退出码 ｜ 11/18 · 第 3 张

②A 讲清了"服务生去找厨师"。这张只回答一个问题：服务生去哪找？凭什么找得到？

一、两个现象，一个原因

现象一：ls（Windows 上是 dir）你在任何目录下敲都能用。

现象二：python 进度.md 换个目录敲，就报"找不到文件"。

同一条命令里的两半，规矩完全不一样：

去哪找跟你站在哪有关吗
第一个词（程序名）去 PATH 清单里的目录逐个找无关
后面的词（参数）按当前目录或你写的路径找完全有关
一句话：程序名靠「通讯录」找，参数靠「你现在站哪儿」找。

二、PATH 是什么

PATH 就是一串目录名，shell 拿着它按顺序挨个翻，翻到就停。

它是电脑里的通讯录：名字在里面，报个名就能联系上；不在里面，你得写清楚"他住哪"（完整路径）才行。

所以"装了软件却用不了"，绝大多数不是没装，是装的位置没写进这张通讯录。

三、命令 = 程序名 + 参数

把一行命令拆开看：

你敲的程序名参数
python 实验.pypython实验.py
cd D:\研究生cdD:\研究生
ros2 topic listros2topic、list

带 - 或 -- 的参数叫选项，是给程序的一种"要求"：ls -l 里的 -l 意思是"列详细一点"。

点菜：菜名（程序名）后厨必须有；少冰、大杯（参数）是这道菜的做法要求。
后厨没有的菜，写多少要求都没用——这就是 command not found。

四、怎么做：亲自问 shell

想知道 shell 从哪儿找到某个程序，直接问它：

系统查程序在哪看通讯录
Windowswhere pythonecho %PATH%
Linux / WSLwhich python3echo $PATH

如果 where python 打印出好几行——说明通讯录里有好几个同名的人，shell 会用第一个。

五、命令跑完，成没成？——退出码

很多命令跑完屏幕一个字都不出。那你凭什么判断它成功了？

凭退出码：每个进程结束时会交给 shell 一个数字。

  • 0 —— 成功
  • 非 0 —— 失败，不同数字代表不同原因

反直觉的地方：屏幕上没字 ≠ 成功。有的程序失败了也一声不吭，只在退出码里留个 1。

快递员送完货会回去交差：「送到了」（0）或 「家里没人」（非 0）。
你不问，他也走了。

怎么查：紧接着上一条命令敲下面这句：

系统命令
Linux / WSLecho $?
Windows PowerShellecho $LASTEXITCODE
Windows cmdecho %errorlevel%

日常还有一个用法：命令A && 命令B —— 只有 A 返回 0，B 才会跑。

六、以后在无人机里怎么用

以后你会打出来的字这张卡的哪一块
source /opt/ros/humble/setup.bash往 PATH 里加目录——这条命令干的就是这件事
ros2: command not foundPATH 里还没有 ros2，说明你忘了 source
cd ws && colcon build退出码 + &&
训练脚本跑了一夜没人看，成没成？退出码，不是"屏幕没报错"

为什么这跟你有关：你以后每天开工的第一条命令，多半就是 source。它不神秘——就是把新目录加进通讯录。

七、自测（先自己想，再点开）

1. 为什么 ls 在哪都能用，python 进度.md 却不行？

ls 是程序名，在 PATH 里，跟你在哪无关；进度.md 是参数，按当前目录算，换个目录就指错了。

2. 两个 PATH 目录里各有一个同名程序，跑哪个？

按 PATH 里的顺序，排在前面的那个。shell 翻到就停，不会继续找。

3. 装了 Python 却报 command not found，最可能的原因？

装了，但它的安装目录没写进 PATH。这时候重装也没用，要改的是 PATH。
