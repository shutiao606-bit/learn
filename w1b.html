②A 一条命令怎么跑起来

只有三个角色 ｜ 11/17 · 第 2 张

必会 2 道 · 该懂 2 道 · 知道 0 道

这张卡只讲一件事：你敲下回车到屏幕出结果，中间是谁在干活。

不讲 PATH，不讲参数，不讲退出码——那些留给 ②B。一次只想通一件事。

一、为什么必须先懂这个

因为你迟早会撞上这三句话，而它们对应的是完全不同的三个原因：

屏幕上的字真正的原因
command not found系统里没有这个程序，或者它不在搜索清单里
No such file or directory程序找到了，但它要打开的那个文件不存在
Permission denied程序和文件都在，但你没有权限动它

不懂这三个角色，你看到第一句只会想"是不是没装"。懂了，你第一反应是"它连程序都没找到，跟文件没关系"。

二、三个角色

1. 终端（Terminal）—— 那个黑窗口

它的工作只有两件：收下你敲的字、把结果打出来。

它自己一个字都不懂。就像餐厅门口的取号机，它只负责把你的单子递进去。

2. Shell —— 看懂你写的那行字的人

Windows 上叫 cmd 或 PowerShell，Linux 上通常叫 bash。它做的事：

  • 把这一行拆成几个词
  • 拿第一个词去找对应的程序
  • 找到就把它启动起来

它是服务生：听得懂你说什么，负责去后厨把人叫出来，但炒菜的活它不干。

3. 程序 / 进程 —— 真正干活的

shell 找到的那个东西。它开始运行，就是 ③ 卡里说的进程。干完活就消失。

它是厨师：只看订单做菜，做完了这单就结束。

完整画面：
取号机（终端）收下你写的单子 → 服务生（shell）看单子、去后厨叫厨师 → 厨师（程序）炒菜、装盘 → 菜端回你桌上（屏幕）。

关键：如果单子上写的菜后厨没有，服务生当场就会告诉你"没有这道菜"（command not found），根本不会有厨师动手。

三、四步，一步不错

① 终端 · 取号机收下你敲的一整行字。它自己一个字都不懂
这一行字 ↓
② shell · 服务生拆成几个词，拿第一个词去找程序
找到程序，把它启动 ↓
③ 程序 · 厨师真正干活的那个。跑起来就是一个进程
结果写回屏幕 ↓
屏幕你看到的那一屏字

这张图每 6 秒从上往下亮一遍：亮到哪一步，就是哪一步在干活。

  1. 回车 —— 终端把这一整行字交给 shell
  2. shell 拆词并找程序 —— 第一个词当作"程序名"，去找它（去哪找，是 ②B 的内容）
  3. 启动 —— 找到了，就开一个新进程，把后面那些词一起交给它
  4. 运行并回话 —— 进程干活，结果写到屏幕，进程结束

记住第 2 步：只有第 2 步会失败得这么早。它一失败，第 3、4 步压根不会发生。

四、报错断在哪——这是这张卡的全部意义

报错断在第几步说明什么
command not found第 2 步shell 没找到这个程序，厨师没上岗
No such file or directory第 4 步厨师上岗了，但它要开的文件不在
Permission denied第 4 步厨师上岗了，文件也在，但不让动

所以判断方法很简单：报错里出现的是"命令"这个词 → 第 2 步；出现的是文件路径 → 第 4 步。

一句话记住：报错说的是"命令"，找的是服务生的麻烦；报错说的是"文件"，找的是厨师的麻烦。
① 终端收下这行字
↓
② shell 找程序没找到 → 断在这里command not found
↓ 找到了，启动
③ 程序跑起来要开的文件不在 / 不让动 → 断在这里file / permission

红标就是报错的位置。看它断在第几层，就知道该查什么。

五、以后在无人机里怎么用

以后你会打出来的字对应这张卡的哪一步
ros2 launch px4 ... 一次拉起十几个节点第 2 步：找 ros2 这个程序
ros2: command not found第 2 步断了 —— 十有八九是没 source 环境（②B 讲）
Error: file not found: model.sdf第 4 步断了 —— Gazebo 跑起来了，但模型文件路径不对

为什么这跟你有关：以后你在仿真里调半天，一半时间会花在这两类报错上。能一眼分出"是找不到程序"还是"是找不到文件"，排查时间能从半小时降到两分钟。

六、自测（先自己想，再点开）

1. 终端和 shell 的区别，一句话怎么说？

终端只管收字和显示，一个字都不懂；shell 才看懂那行字、负责找程序并启动它。

2. 敲一个根本不存在的命令，会有厨师上岗吗？

不会。shell 在第 2 步就没找到程序，直接报 command not found，后面什么都没发生。

3. 为什么"报错说的是命令还是文件"，能帮你判断断在哪？

因为这两句话是不同角色喊出来的：第 2 步是 shell 在喊"没有这个命令"，第 4 步是程序在喊"没有这个文件"。
